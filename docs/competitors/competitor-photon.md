# Competitor teardown: Photon (Fusion, Quantum, Realtime, PUN, Chat, Voice, Video, Photon Server, Photon Cloud) vs musubi

| | |
|---|---|
| **Product** | Photon Engine (Exit Games): Realtime 5 (rooms/relay/matchmaking core), Fusion 2 (Unity state-sync netcode; Fusion 3 ports for Unreal/Godot/C++ Core in preview), Quantum 3 (deterministic ECS predict/rollback), PUN 2 (legacy Unity, LTS), Chat, Voice 2, Video 2, Photon Server 5/6 (self-hosted), Photon Cloud (Public/Premium/Enterprise), Tournament SDK (stale 2022), Realtime Core 6 (C++20 preview) |
| **Pricing / licensing** | Proprietary, closed source (client SDKs are source-available C#, server core is binary). Public Cloud: 20 CCU free dev-only (hard cap), Free100 = 100 CCU free for one Fusion/Quantum title, 100 CCU $95 one-off/12 mo, 500 CCU $95/mo, 1000 CCU $185/mo, 2000 CCU $370/mo (3 GB traffic per peak CCU, overage $0.05–0.10/GB, overage CCU $0.75–1.00); Premium Cloud $0.29/CCU from $580/mo, auto-scales to 50k CCU; Enterprise Cloud dedicated bare metal, SLA, custom server plugins. Photon Server self-hosted needs a `.license` file (free dev licenses, commercial on request, floating licenses phone home). Server-side custom code (plugins) is gated to Enterprise Cloud or self-hosted Windows server. |
| **Hosting model** | Managed SaaS relay/room servers in 16 regions (Master + Game servers per region, NameServer front door); Photon does **not** host your Fusion dedicated game servers (bring Multiplay/Hathora/Gameye/Docker). Self-hosted option = Photon Server on Windows Server only (no Linux, no containers). Enterprise = dedicated private cloud operated by Photon. |
| **SDKs / platforms** | Unity (Fusion 2, Quantum 3, PUN 2, Realtime, Chat, Voice, Video), Unreal (Realtime C++, Chat, Fusion Unreal 3 preview on Fab), Godot 4.6 (Fusion Godot 3 preview), C++20 (Realtime Core 6, Fusion Core 3 on request), .NET, JavaScript/TypeScript, Java/Android, Objective-C, Emscripten/WebGL/WASM, Discord Activities; consoles PS4/PS5/Switch/Switch 2/Xbox One/Series behind gated docs; XR (Quest, visionOS, HoloLens 2, MagicLeap). |
| **Release cadence** | Fusion 2.1: weekly-ish builds (nightly Aug 2025 → preview Apr 2026 → RC Jun 2026 → stable 2.1.0 Jun 30 2026, 2.1.3 Sep 17 2026). Quantum 3.0.x stable every ~6–8 weeks (3.0.2 Apr 2025 … 3.0.14 Oct 5 2026), 3.1 preview (plugin SDK 3.1.0 Oct 15 2026). Realtime 5.1.x monthly (5.1.10 Feb 2026 → 5.1.18 Aug 2026, SDK download now 5.1.20). Realtime Core 6 preview builds Sep 23 / Oct 15 2026. Fusion Unreal 3 preview builds Oct 7/12 2026. Bot SDK 3.10.6 Oct 16 2026. PUN 2 maintenance only. Tournament SDK last release Dec 2022. |
| **Last release date** | Bot SDK 3.10.6 — 16 Oct 2026; Quantum Plugin SDK 3.1.0 / Realtime Core 6 build 414 — 15 Oct 2026; Fusion Unreal build 1659 — 12 Oct 2026; Quantum 3.0.14 — 5 Oct 2026; Fusion 2.1.3 — 17 Sep 2026 |
| **musubi baseline** | Apache-2.0 Rust backend, 476 HTTP routes (`crates/musubi-server/src/openapi.rs`), realtime protocol over WS/QUIC/WebTransport/WebRTC/UDP (`crates/musubi-proto/src/realtime.rs`), 122 migrations, 21 crates, Helm/Terraform deploy, CLI (bench/soak/doctor/deploy/transfer). Alpha: no client SDKs (Unreal scaffold only), no admin console UI. |

## Top gaps for musubi

Ranked by how much a studio choosing between Photon and musubi would care.

1. **Client SDKs (Unity/C# first, then JS/TS, C++, Godot)** — `missing`. Photon ships Unity, Unreal, Godot, C++, .NET, JS, Java, ObjC, WebGL, consoles. Sketch: generate a C# client from `openapi.rs` + a hand-written realtime client (postcard codec, 4 reliability channels, reconnect/rejoin) packaged as UPM; mirror for TS.
2. **Engine-level state replication (Fusion `[Networked]`/Quantum ECS equivalent)** — `partial`. musubi has IDL deltas but no in-engine prediction/interpolation/change-detection. Sketch: Unity package that binds IDL-generated types to MonoBehaviours with tick buffer, snapshot interpolation, client prediction + reconciliation against `match_state_delta`.
3. **Deterministic rollback option (Quantum)** — `missing`. Sketch: separate Rust `musubi-deterministic` crate: fixed-point math, input-only relay mode in `musubi-actor` (server batches confirmed inputs per tick, no state), checksum/desync detection, replay = input log; client sim is a game-side library.
4. **Lag compensation primitives** — `missing`. Sketch: in `musubi-sim-sdk` add hitbox history ring buffer keyed by tick + RTT-based rewind queries (raycast/sphere/box) for authoritative match code.
5. **Admin console / dashboard UI** — `missing`. Photon's dashboard (AppIds, counters, webhooks config, team permissions) is table stakes. Sketch: web console over existing admin routes: CCU/rooms/bandwidth charts from Prometheus, config/env editing, module canary controls, player lookup, moderation queue.
6. **Voice (and video)** — `missing`. Photon Voice relays Opus over rooms with VAD/interest groups/moderation forwarding. Sketch: WebRTC SFU sidecar (e.g. integrate an existing Rust SFU) issued tokens by `musubi-auth`, room-scoped, with interest-group routing and moderation forwarding hooks — or document Aurix integration as first-class.
7. **Managed/hosted offering & regions** — `n/a`-ish but decisive commercially. Studios compare "sign up, get AppId, 100 CCU free" to running Postgres+cluster. Sketch: one-click Terraform/Helm "region pack" + hosted alpha; publish CCU-per-node benchmarks.
8. **Client host with NAT punch-through / direct P2P** — `partial`. Fusion Client Host and Realtime Core direct messaging do STUN punch + relay fallback. Sketch: STUN/ICE candidate exchange over the realtime channel using the existing WebRTC DataChannel transport; relay fallback already exists.
9. **Per-object send priority / per-player replication rate** — `missing`. Sketch: in `musubi-mesh` ghost replication add per-entity-per-subscriber priority (send every N ticks) and distance tiers; expose `set_priority` in match API.
10. **Turn-based / async matches** — `missing`. Sketch: `async_match` table (state blob, turn owner, deadline), `/v1/matches/async` routes, turn notifications via push/mail, Async-lobby style listing by participant.
11. **Event cache for late joiners** (Realtime cached events) — `missing`. Sketch: optional per-relay-match event cache (global/actor scopes, remove/slice ops) replayed to joiners before live stream.
12. **Dedicated Oculus/Meta, Viveport, Epic EOS auth providers + PlayFab auth bridge** — `partial`. Sketch: add OIDC-like verifiers in `musubi-auth` (Meta nonce verify, EOS JWT JWKS, Viveport token check).
13. **Input delay / tick-timeline tuning exposed to clients** — `missing`. Sketch: server advertises tick, send rate, recommended input lead in `match_joined`; add `input_delay_ticks` to match config.
14. **Console SDK story (PS/Switch/Xbox)** — `missing`. Sketch: C++ core SDK (see gap 1) + certification notes; auth providers already exist.
15. **AppVersion-style build isolation and per-app region allowlists** — `partial`. Sketch: first-class `client_version` claim in session → matchmaker/lobby pool key; `allowed_regions` in app config.
