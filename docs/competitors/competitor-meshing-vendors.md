# Competitor scan — Server meshing / distributed simulation vendors vs musubi

Key: `meshing-vendors`. Scope: Hadean (Aether Engine / Hadean Platform SDK), coherence, Improbable SpatialOS (archived docs + GitHub), Flax Engine high-level networking (stand-in for "Flax/Ultra Horizon style" engine netcode; Ultra Horizon has no public material), Star Citizen replication layer / hybrid service / server meshing (public talks, patch notes, community wiki). musubi baseline: https://github.com/musubi-oss/musubi @ main, read 2026-10-18 (README, docs/parity.md, openapi.rs ROUTES, musubi-proto realtime.rs, crates/, migrations, musubi-cli, deploy/).

## Top gaps for musubi (ranked by studio impact)

1. **No engine SDKs (Unity missing, Unreal scaffold not CI-built)** — coherence ships a full Unity no-code layer; SpatialOS had GDKs for Unreal+Unity; Flax is in-engine. Sketch: generate typed client from `GET /openapi.json` + `musubi-proto` (postcard) into a C# UPM package and a UE plugin; CI-compile both; ship `WorldSubscribe/WorldDelta` bindings first.
2. **2-D cells only, no 3-D/octree partitioning** — Hadean Aether, SpatialOS and coherence LiveQueries are 3-D. Sketch: generalise `CellId` to (depth, x, y, z) with octree split in `musubi-mesh`, keep quadtree as the z-flat special case; add `z` to `WorldEntity`/`world_subscribe`.
3. **No non-spatial partitioning / offloading by entity type** — SpatialOS `entity_id_sharding` + Unreal GDK Actor-Group offloading, layers per component. Sketch: add `partition_key` strategy to `CellId` ("non-spatial partition keys plug into CellId later" per lib.rs) so a world can run e.g. an AI layer on dedicated simulators.
4. **No network LOD / per-field quantization schema** — coherence archetypes (bits, range, FixedPoint, per-LOD component drop), SpatialOS component delivery, GDK `CompressedQuaternion`. Sketch: IDL `[components.X.fields.y] bits/range/lod_distance`; apply in `musubi-mesh` interest encoder per client distance.
5. **No visual inspector / admin console** — SpatialOS Inspector (entities, worker load, authority & interest regions), Unreal Spatial Debugger, coherence dashboard. Sketch: web UI over `/v1/admin/worlds/{w}/entities`, `view/{x}/{y}`, `cluster/worlds`, drawing cell leases, ghosts and per-client interest.
6. **No client-side prediction / interpolation / rollback helpers** — coherence per-binding interpolation, extrapolation, CoherenceInput + prediction; Flax Replicated-Simulated role. Sketch: SDK-side `InterpolationBuffer` + `InputHistory` reconciling against `WorldDelta.tick`; expose server `history_ticks` for reconcile windows.
7. **No client-authority / request-steal authority model** — coherence lets any entity be client-owned with Request/Steal/Not-transferable transfer; Flax ownership scopes. Sketch: `authority: client|server` per spawn with `POST /v1/server/worlds/{w}/authority/request` and server-side validation hooks.
8. **Single radius query per client; no tag/global/multi-query interest** — coherence Live/Tag/Global queries (15 per client), SpatialOS QBI (and/or/not, sphere/box, per-query frequency). Sketch: `world_subscribe` accepts `queries: [{shape, filter, max_hz}]` unioned per client; add `always_relevant` component flag.
9. **No generated typed RPC/commands with routing targets** — coherence commands (AuthorityOnly/Other/All/InputAuthorityOnly, ordered, meta), SpatialOS component/world commands with deadlines. Sketch: IDL `[commands.X]` → generated `interact` payloads with target mode and deadline/status codes.
10. **No per-entity/per-component replication rate** — coherence per-field sampling, Flax `ReplicationFPS`, SpatialOS QBI frequency. Sketch: component-level `max_hz` in world params and IDL, honoured by the interest encoder.
11. **No memory-pressure admission control** — coherence `GOMEMLIMIT` 85 %/95 % thresholds; SpatialOS Platform Edition caps. Sketch: node RSS watermark in `musubi-cluster` → reject new world subscriptions / shed lowest-value cells.
12. **No engine-driven simulated players** — SpatialOS simulated-player deployments, Unreal GDK `createsim`. Sketch: `musubi soak --sim-client <binary>` fleet provider that launches headless clients against a world.
13. **No world-wide hard entity cap / per-client owned-entity caps** — coherence `--max-entities`, 32 768 per client. Sketch: `max_entities` world param + per-session spawn quota in `realtime/world.rs`.
14. **No Epic Games login, no Steam Datagram Relay / EOS P2P transport** — coherence auth + client-hosting relays. Sketch: add `epic` OIDC provider in `musubi-auth`; relay adapter in `musubi-transport` is lower priority.
15. **No published >2k-CCU single-world benchmark** — Hadean 14k, Star Citizen 1–2k shards, SpatialOS 1000 worker connections/deployment. Sketch: extend `soak.yml` with a 5k-client multi-node world scenario and publish numbers.
