# Competitor teardown: Nakama server + Nakama Console + Heroic Cloud (Heroic Labs) vs musubi

| | |
|---|---|
| **Product** | Nakama server (open source, Apache-2.0) · Nakama Enterprise (clustered build, Heroic Cloud / private cloud only) · Nakama Console (embedded admin UI) · Heroic Cloud (managed hosting) · adjacent paid products Hiro (metagame framework) and Satori (LiveOps) |
| **Pricing / licensing** | Nakama OSS: Apache-2.0, free, single node. Nakama Enterprise: not sold as a standalone binary — comes with Heroic Cloud (usage-based, per CPU tier, billed daily via Stripe) or Private Cloud (contact sales). Paid add-ons: support plans (SLA, assigned engineer, load tests), Enterprise SSO/SCIM, metric export, log export, DB replica, profiling. Hiro and Satori are separately licensed. Console SDKs (Xbox/PS/Switch) are closed source, handed out after platform approval. |
| **Hosting model** | Self-host OSS (Docker/binary + PostgreSQL-compatible DB; CockroachDB "official", PostgreSQL "unofficial/dev" per install docs, though docker-compose ships Postgres) or Heroic Cloud (GCP regions US/EU/Asia, AWS on request; dedicated LB + Nakama nodes + PostgreSQL per deployment; HA at ≥2 vCPU; no autoscaling, manual tiers Nano 1 CPU → 7XLarge 120 CPU). Private Cloud in customer account with VPC peering. |
| **SDKs / platforms** | Unity/.NET, Unreal (C++), C++, JavaScript/TypeScript (+Cocos2d-x JS), Java/Android, Swift, Dart/Flutter, Godot 3, Godot 4, Defold (Lua), Cocos2d-x C++; console SDKs for Xbox Series X/S, Xbox One, PS5, PS4, Switch (C++/Unreal, Unity). Protocols: REST, gRPC, WebSocket, rUDP. Server runtimes: Go plugins, Lua 5.1, JavaScript/TypeScript. |
| **Release cadence** | 104 releases since 0.10.0 (2017-01-14); 3.x minor every ~1–2 months in 2025–2026 (3.27 May-25, 3.28 Jul, 3.29 Jul, 3.30 Aug, 3.31 Sep, 3.32 Sep, 3.33 Oct, 3.34 Nov, 3.35 Dec, 3.36 Jan-26, 3.37 Feb, 3.38 Mar, 3.39 May, 3.40 Jul, 3.41 Sep) plus patch releases; nakama-common tracks server (1.48.0). |
| **Last release** | Nakama 3.41.0 — 2026-09-18 (nakama-common 1.48.0 same day); `[Unreleased]` section already lists console 404 hardening, FleetManager namespace init change, Google aud/azp fix. |
| **musubi baseline used** | musubi-oss/musubi @ main (alpha): README feature table (583 lines), docs/parity.md, 538 HTTP routes in `crates/musubi-server/src/openapi.rs`, 39 client / 37 server realtime messages in `musubi-proto/src/realtime.rs`, 22 crates, 122 migrations, CLI (`dev module fleet schema idl deploy migrate migrate-nakama migrate-playfab export import doctor config bench soak`), `deploy/` (Dockerfile, Helm, Terraform k8s/Hetzner/OVH), `sdk/unreal`. |

Status legend: **have** = musubi clearly has it (evidence cited) · **partial** = exists but weaker (what is weaker stated) · **missing** = nothing comparable after `rg` · **n/a** = not meaningful for a self-hosted OSS backend.

## Top gaps for musubi

Ranked by how much a studio choosing between the two would care.

1. **Client SDKs for Unity/.NET, Unreal (full), Godot 3/4, JS/TS, C++, Swift, Java/Android, Dart, Defold, Cocos2d-x** (`missing`). Nakama's biggest moat is 11 maintained SDKs with auto session refresh and a shared socket adapter. Sketch: generate REST clients from `GET /openapi.json` (musubi IDL already emits schemas) per language, hand-write one socket adapter per platform reusing `realtime.rs` enums; ship Unity + Godot + JS first.
2. **Admin console UI** (`missing`). Nakama Console: players/groups/storage/leaderboards/chat/matches/payments/notifications browsers, API explorer, runtime modules, config export, data reset, role-based console users + ACL templates + MFA. Sketch: a static SPA served by the server binary at `/console` over the existing 93 `/v1/admin/*` routes + operator roles/SSO; start with players, storage, leaderboards, API explorer.
3. **Scripting runtimes (Lua / JavaScript-TypeScript) and Go plugins** (`partial`). musubi only runs WASM Component modules; most Nakama studios write TS/Lua. Sketch: add a JS runtime via `javy`/QuickJS-to-WASM pipeline so `.ts` bundles compile to the existing module ABI; document AssemblyScript/TinyGo/Rust targets.
4. **Generic before/after hooks on every API + realtime message, "disable API by returning nil"** (`partial`). Nakama has ~85 Before/After pairs + `BeforeRt/AfterRt`. Sketch: a middleware layer in `musubi-server` that dispatches `hook_before_<route_id>` / `hook_after_<route_id>` to modules when registered, with the request/response JSON as payload; plus `[api] disabled_routes`.
5. **Console SDKs for Xbox / PlayStation / Switch clients** (`missing`). Server-side auth exists; the client libraries under NDA do not. Sketch: once the C++/Unreal SDK exists, add platform auth helpers and distribute through the platforms' middleware directories.
6. **Game-console / platform IAP breadth: Huawei, Facebook Instant Games, Samsung Galaxy Store, Unity IAP wrapper, PSN/Xbox/Nintendo stores** (`missing`). Sketch: provider trait in `musubi-economy` IAP module already handles Apple/Google/Steam; add Huawei (public-key RSA verify), Samsung (`package_name` + receipt API), FB Instant (`app_secret` signed request).
7. **Streams primitive for module code** (`missing`). Nakama lets modules create arbitrary pub/sub streams (join/leave/kick/send/count/close). Sketch: expose the internal presence/bus topic API as `stream.*` host ops with (mode, subject, subcontext, label) ids and `hidden`/`persistence` flags.
8. **Matchmaker override / processor hooks** (`partial`). Nakama lets modules reorder candidate matches or take over grouping of the whole ticket pool. Sketch: `hook_matchmaker_override(candidates)` and `hook_matchmaker_process(pool)` called by the owning node per pass, with a time budget.
9. **Storage search index semantics: boosting, regex, fuzzy/prefix terms, `sortableFields`, index-only reads, per-index filter callback** (`partial`). Sketch: extend `query.rs` grammar to full Bleve subset and compile to Postgres `tsquery`/`jsonb` + GIN; add `hook_storage_index_filter`.
10. **Party label/hidden flag + party listing/search API** (`partial`). Sketch: add `label`/`hidden` to `PartyCreate`/`PartyUpdate`, replicate labels over the bus, `GET /v1/parties?query=` using the matchmaker query grammar.
11. **Raw HTTP handler registration from modules (`RegisterHttp`, `RegisterConsoleHttp`) and shutdown hook** (`missing`). Sketch: `[[modules.http_routes]]` manifest entries routed to a module export; `hook_shutdown` with `shutdown_grace_sec`.
12. **GDPR tombstones (recorded delete)** (`partial`). Nakama writes a tombstone so a restored backup can be re-purged. Sketch: `account_tombstones` table + `DELETE /v1/admin/accounts/{id}?record=true`, checked by `musubi import`/`restore`.
13. **Per-owner extra tournament attempts (`TournamentAddAttempt`) and `LeaderboardRanksDisable`** (`partial`). Sketch: `POST /v1/server/tournaments/{id}/attempts/{owner} {count}`; `ranks: false` flag that skips rank window computation for huge boards.
14. **Runtime host API breadth: raw SQL, token minting (`AuthenticateTokenGenerate`), `NotificationSendAll`, localcache, `CronNext/Prev`, `MultiUpdate` atomic storage+wallet** (`partial`). Sketch: add host ops behind an `unsafe_sql` capability flag; `notifications.broadcast` with audience filter; `cron.next`.
15. **CockroachDB / distributed-SQL support and gRPC transport** (`partial`). Nakama runs on any Postgres-wire DB incl. CockroachDB and exposes gRPC. Sketch: CI matrix against CockroachDB (drop `LISTEN/NOTIFY` dependency behind a bus trait); optional tonic gRPC façade generated from the IDL.
