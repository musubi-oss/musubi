## Top gaps for musubi

Ranked by how much a studio choosing between EOS and musubi would care (weight: breadth of studios affected × switching pain). Status in brackets; one-line implementation sketch each.

1. **Client SDKs (C/C++ with stable ABI, C#, Unreal OSS/Online Services plugin, Unity plugin) [missing]** — EOS ships one C ABI + wrappers for every engine/platform; musubi only has an OpenAPI spec and an Unreal scaffold. Sketch: generate a C ABI client (`musubi-client` crate with `cbindgen`) from the IDL/OpenAPI, wrap it for C#/Unity and finish the Unreal subsystem (auth, storage, lobbies, matchmaker, WS/QUIC socket, resumable sessions).
2. **Easy Anti-Cheat equivalent (protected client mode, client module delivery, integrity catalog, client-server & P2P validation, kick reasons, auto-sanctions) [missing]** — musubi only relays EAC/BattlEye tickets and accepts anti-cheat signals. Sketch: keep integrating EAC/BattlEye as providers but add first-party pieces that are backend-side: signed file-integrity manifests per build (`/v1/fleets/builds/{id}/integrity`), server-side heuristics on trusted gameplay data (hit/damage telemetry in match actors), and sanction automation from the anticheat flag API.
3. **Built-in voice (RTC rooms per lobby/party, up to 64, mute/hard-mute/kick, device & DSP control, RTC-data) [missing]** — musubi relies on Aurix tokens. Sketch: add a `musubi-rtc` SFU node (WebRTC/Opus via `webrtc-rs` or an embedded LiveKit/mediasoup) with room tokens minted per lobby/party and lobby owner moderation hooks; keep Aurix as a pluggable provider.
4. **P2P NAT traversal + relay (STUN/TURN, relay control modes, NAT type query, encrypted channels) [missing]** — needed for listen-server/P2P games. Sketch: ship a `musubi-relay` (TURN/ICE with `webrtc-ice`/`str0m`) deployable as a fleet provider, with `/v1/rtc/ice` credential minting per session and relay-control policy (allow/no/force) stored on the lobby.
5. **Developer/admin console (lobbies & sessions browser, player search with data-rights export/delete, achievements/stats/leaderboards editors, reports & sanctions queues, analytics dashboards, client policies) [missing]** — EOS' Developer Portal is the daily tool for ops/support; musubi exposes everything only via admin HTTP API. Sketch: a React/SvelteKit console shipped in the binary (served under `/console`) driven by `GET /openapi.json`, starting with player search/data rights, moderation queues and content editors.
6. **Sanctions as a first-class service (typed action catalogue incl. RESTRICT_GAME_ACCESS / RESTRICT_MATCHMAKING, durations, pending/approve, tags/justification, client-queryable active sanctions, appeals with hosted form, CSV export) [partial/missing]** — musubi has bans + age-bracket feature closure only. Sketch: `sanctions` table (account_id, action, expires_at, status, justification, tags, source report/anticheat id), `GET /v1/account/sanctions`, enforcement hooks in matchmaker/lobbies/chat, appeal endpoints + moderator queue, Web API parity.
7. **Hosted account portal / consent & scope model (OAuth-style scopes, per-app consent, revocation, hosted login, email verification/reset UI) [missing]** — important once a studio has several titles or third-party tools. Sketch: minimal hosted auth pages (login, register, reset, consent) served by the binary, `oauth_clients`/`grants` tables, scope claims in JWT, consent revocation endpoint.
8. **Verifiable parental consent / age verification (KWS: guardian email flow, card/ID/face/SSN verification providers, AgeGraph, webhooks) [partial]** — musubi has brackets and a consent token but no verification path. Sketch: `musubi-integrations` provider trait for VPC vendors (Kids Web Services itself, Veriff, k-ID), guardian-email flow with signed callbacks, webhook into existing `[compliance]` feature closure.
9. **Social Overlay / in-game UI layer (friends, invites, party, achievements, notifications, request-to-join, block/report dialogs) [missing]** — UI is out of scope for a backend, but the backing APIs should be complete. Sketch: ship an engine-agnostic UI widget kit (UMG + Unity UI prefabs) over the SDK once SDKs exist; add `request_to_join` to lobbies/parties where not yet symmetric.
10. **Localized rich presence templates with variables (portal-managed, per-locale text, up to 8 variables) [missing]** — Sketch: `presence_templates` content collection (template_id, default_locale, locale→text, variable definitions) delivered via `/v1/configs`, server-side rendering in `StatusPresenceEvent` according to viewer `lang`.
11. **Per-action client policies (local-user vs any-user vs trusted-server grants per API action, IP allow-list for trusted servers) [partial]** — musubi roles are coarse (player/server/admin roles) with per-key scopes. Sketch: extend scoped keys with an action matrix (`policy` JSON: {achievements: [find, unlock_local]}), add `allow_cidrs` on server keys, surface in OpenAPI `x-musubi-policy`.

### What could not be accessed / caveats

- `https://dev.epicgames.com/docs/epic-online-services` (section root) returns HTTP 403 (Cloudflare challenge) to non-browser clients; the sitemap was used instead. After ~100 fast requests the site rate-limited the crawler (HTTP 429); the remaining pages were fetched sequentially with back-off.
- `https://dev.epicgames.com/docs/epic-online-services/release-notes` stayed 429 for the live fetch; it was read from the web.archive.org snapshot of 2026-08-22 (covers through 1.18.1.2). Versions 1.0–1.12 (pre-2021) are not on the public release-notes page at all.
- Console-specific SDK documentation (PS4/PS5/Xbox/Switch pages) is behind Developer Portal console access approval and was not readable. The EOS SDK API reference (`/docs/api-ref/*`, ~1,500 generated pages) and the Developer Portal product itself were not walked page by page; interface capabilities were taken from the guides/reference pages, client-policy action lists and error-code list instead.
- EOS has no public source repository, OpenAPI or protobuf definitions (closed SDK); the only open component is the community EOS Plugin for Unity (github.com/EOS-Contrib/eos_plugin_for_unity), which was not scanned.
- Pricing: Epic does not publish a pricing page for EOS (it is free); anti-cheat paid tiers are described only qualitatively on easy.ac — no prices available.
