# Competitor scan: Edgegap vs musubi

**Scan date:** 2026-10-18. **Musubi baseline:** `musubi-oss/musubi` `main` as checked out on 2026-10-18 (469 unique `/v1/...` routes in `crates/musubi-server/src/openapi.rs`, 122 migrations, 24 crates, Unreal SDK scaffold only, README: "client SDKs and the admin console are not written yet").

|---|---|

| Pricing / licensing | Proprietary SaaS. **Free tier**: 2 apps, 2 versions, 10 GB registry, free shared matchmaker/server-browser clusters (auto-stop after 3 h), 1-min metrics history. **Pay-as-you-go** (per vCPU-hour usage; unlocks active caching, 1-s metrics, analytics, private fleets, managed clusters). **Private Fleets**: Performance VM 16 vCPU/32 GB $350/$323.75/$280 per month (1/6/12-month commit), Overdrive bare metal 8c16t/64 GB $400/$370/$320, 6 TB egress per host per month, min 1-month commitment, auto-renew. **Private matchmaker / server-browser / managed clusters**: Hobbyist 1 vCPU+2 GB $0.0312/h ($22.46/30 d), Studio 6 vCPU+12 GB $0.146/h ($105.12/30 d), Enterprise 18 vCPU+48 GB $0.548/h ($394.56/30 d). | SDKs / platforms | Unity (Dedicated Servers quickstart plugin; SDK 3.5.5 via UPM with Matchmaking + Server Browser agents; relay transports for Mirror, FishNet, NGO), Unreal (quickstart plugin, Docker Desktop extension, Betide EGIK on Fab), Godot (hosting plugin 1.0.9 on Asset Store), REST API v1 (72 ops) + v2 (3 ops), OpenAPI specs on GitHub, MCP server (`mcp.edgegap.dev`), agent skills repo, Nakama module, UGS allocator, PlayFab CloudScript bridge, EOS lobby guide. ## Top gaps for musubi

Ranked by how much a studio choosing between the two would care.

1. **Engine SDKs / editor plugins (Unity, Unreal, Godot) — `missing`.** Edgegap's one-click build→containerize→upload→deploy from the editor plus Matchmaking/Server Browser agents is the onboarding story. Sketch: `sdk/unity` UPM package (C# client for auth/socket/matchmaker/lobbies) + editor window that runs `docker build` and `musubi fleet push`; mirror for Godot GDExtension; finish `sdk/unreal`.
2. **Admin console — `missing`.** Deployments map, logs, metrics, fleets, matchmaker status, players. Sketch: static SPA served by `musubi-server` under `/console`, driven only by existing `/v1/admin/*` + `/v1/server/*` routes with the OIDC operator login.
3. **Game-server container logs + metrics (CPU/mem/net/egress, OOM) — `missing`.** Sketch: docker/k8s/firecracker providers stream stdout/stderr and cgroup stats into a `gameserver_logs` table (bounded) + Prometheus `musubi_gameserver_{cpu,mem,net}` labelled by server id; optional S3 sink on termination.
4. **Public server browser for dedicated servers (slots, metadata filters/sort, seat reservation with expiry, bulk confirmation) — `partial`.** Sketch: `GET /v1/servers?filter=<expr>&order=` over `GameServer.labels` with indexed JSONB keys, `POST /v1/servers/{id}/reserve` {players[]} → reservation with 30 s TTL, `POST /v1/gameserver/reservations/confirm` from the server key.
5. **Standalone UDP relay for third-party netcode (Mirror/FishNet/NGO/Unreal) — `partial`.** Sketch: `musubi-relay` binary on edge nodes: session = per-user tokens + IP allowlist, host/client ports, byte forwarding with per-session bandwidth caps; `POST /v1/server/relays/sessions`; ship a Mirror transport first.
6. **Global ping beacons + automated latency measurement — `partial`.** Sketch: every node already runs `[regions] echo_listen`; add `GET /v1/regions/beacons` with ICMP/UDP/TCP endpoints, publish a client ping routine in each SDK that fills `ping_<region>` automatically.
7. **Per-server resource spec: memory limit, grace period, max duration, restart policy — `missing`/`partial`.** Sketch: extend `FleetSpec` with `memory_mib`, `grace_secs`, `max_duration_secs`, `restart: never\|on_crash\|always`; map to `--memory`/`--stop-timeout` (docker), `resources.limits`/`terminationGracePeriodSeconds` (k8s), reaper enforces TTL.
8. **Deployment lifecycle webhooks (`gameserver.ready/error/terminated`) — `partial`.** Sketch: emit these three events on the existing event bus so `/v1/admin/webhooks` subscriptions get them with HMAC + DLQ (already stronger than Edgegap's fire-and-forget).
9. **Secret env vars / credential store (registry pull secrets, hidden env) — `missing`.** Sketch: `secrets` table encrypted with a server master key, `FleetSpec.env_secret_refs`, redact in `musubi config` and admin reads; docker provider does `docker login` from the stored registry profile.
10. **Placement by player IP / geo coordinates with multi-region fallback — `partial`.** Sketch: bundle an IP→geo lookup (MaxMind-compatible mmdb loader), compute centroid of the `users` list, choose the nearest fleet region with capacity, fall back within a configurable radius (Edgegap: 700/1400 km).
11. **Named multi-port mappings with per-port protocol and readiness checks — `partial`.** Sketch: `FleetSpec.ports: [{name, internal, protocol, check}]`, expose `MUSUBI_PORT_<NAME>` env vars and `ports` in `GET /v1/server/gameservers/{id}`.
12. **Session objects with socket accounting (Seat/Match kinds, autodeploy, empty TTL) — `partial`.** Sketch: `sessions` table keyed to `GameServer`, `kind` seat|match, `sockets` per build; `POST /v1/server/sessions` finds a server with free sockets or allocates (`autodeploy`), `empty_ttl` reaper.
13. **Metadata-filter-driven scaling policies — `partial`.** Sketch: `ScalePolicy.rules: [{filter: label expr, min_ready, region}]` evaluated by the reconciler alongside `buffer`, so "keep 2 idle `map=desert` servers in eu" is declarative.
14. **MCP server / agent skills — `missing`.** Sketch: thin MCP wrapper over `musubi` CLI + OpenAPI (deploy, fleet push, module canary, logs once #3 exists) published as `musubi-mcp`; add `.agents/skills` for Unity/Unreal integration.
15. **Operator organisation model (members, invitations, roles, notifications) — `partial`.** Sketch: `operators` + `org_memberships` tables behind OIDC login, map to existing key roles, notification feed table fed by the event bus (rate-limit hits, uncached builds, dead webhooks).
