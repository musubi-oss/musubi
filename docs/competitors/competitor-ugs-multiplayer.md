## Top gaps for musubi

Ranked by how much a studio choosing between UGS multiplayer and musubi would care.

1. **No Unity C# client SDK (Sessions-style)** — ship `com.musubi.sdk` (UPM) with `ISession`-like API over lobbies/matchmaker/matches, auto-heartbeat, event hookup, and an NGO/N4E `INetworkHandler`/`UnityTransport` adapter for musubi relay.
2. **No voice chat engine** (2D/3D channels, PTT, muting, STT/TTS, recording) — either embed a SFU (e.g. LiveKit/mediasoup) behind `/v1/voice/*` with positional mixing metadata, or deepen the Aurix integration to lobby/world channels, moderation kicks/mutes and token claims parity.
3. **No Distributed Authority / client-authority relay with session owner** — add an ownership-aware relay mode on `musubi-actor`: per-object authority table, ownership request/transfer messages, session-owner election, spawn/despawn replication; keep server validation hooks.
4. **No admin console / dashboards** (session viewer, matchmaker logs, fleet analytics, moderation UDash) — build a thin web console over existing admin routes + Prometheus (sessions, tickets, fleets, reports) before studios will evaluate.
5. **Declarative matchmaking rule DSL with staged relaxations, pools and CEL filters** — add JSON `rules[]` (Difference/Equality/InList/Intersection/range on ticket props, team ranges, relaxations by ticket age Oldest/Average/Youngest, CEL pool filters) compiled to the existing scorer; keep WASM for custom logic.
6. **Backfill ticket lifecycle** — add `backfill_tickets` (roster/teams, approval heartbeat with auto-expiry, update releases unassigned proposals, pause/resume) and server SDK `players` → auto-backfill when a slot frees.
7. **Lobby reconnect/disconnect grace + createOrJoin + quickJoin** — add `disconnected_at` on membership with configurable removal/host-migration timers (socket drop → disconnected), `POST /v1/lobbies/create_or_join {id}` and `POST /v1/lobbies/quick_join {filters, create}`.
8. **Lobby query engine parity** — indexed typed properties (S1–S5/N1–N5 style or generic typed keys), EQ/NE/LT/LE/GT/GE on numeric props, sort orders, random sample, per-property visibility public/member/private, per-member data.
9. **Voice/text safety pipeline** (Safe Voice/Safe Text/Text Evidence/incident workflow) — add incidents (aggregate reports, assignee, status, risk score), configurable sanction/honor catalog with durations + revoke, evidence snapshots preserving edited/deleted versions; expose automod hook for external ML filters incl. voice transcripts.
10. **Standalone UDP/DTLS relay allocation with join codes** — expose `POST /v1/relay/allocate {max_connections, region}` → endpoint list + HMAC key + join code, for engines using UTP/ENet-style transports (console/WebGL variants: udp/dtls/wss).
11. **Matchmaker observability** — per-ticket lifecycle log (created/pooled/proposed/matched/expired) with match-builder snapshots on expiry and stored `matchmaking_results` by match id; queryable via API.
12. **Matchmaker A/B testing of rules** — queue variants with traffic split + `variant_id` on the ticket, outcome stats (wait time, quality grade, retention via Zanshin) per variant.
13. **Game server SDK depth** — Unity/Unreal server plugins; SQP/A2S query listener (occupancy, map, build id); allocation idle TTL reaper; log/crash-dump capture to object storage; file-based config (`server.json`) for engines that cannot read env/HTTP.
14. **Hybrid/multi-location fleets** — allow several providers/locations inside one fleet region with priority/cost ordering and redundancy; delta/mirrored build distribution for large binaries.
15. **Packet-loss-aware QoS + client QoS SDK** — measure latency and loss per region in client SDKs and let queues constrain on both.
