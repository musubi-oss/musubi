# Competitor teardown: Hathora Cloud vs musubi

**Product:** Hathora Cloud — managed orchestration of containerised dedicated game servers (rooms/processes) with a thin Lobby Service; later repositioned as "Elastic Metal" hybrid CPU/GPU compute orchestration (load-balanced apps, inference, CI runners). **Status (Oct 2026): discontinued.** Hathora was acquired by Fireworks AI; `hathora.dev/docs`, `/api` and `/changelog` now 301 to `gamefabric.com` (GameFabric is the designated transition partner, platform frozen, shutdown after a 90-day window). Everything below is reconstructed from Wayback Machine snapshots (2023-09 → 2025-09), the archived `swagger.json` (107 paths / 115 operations), the still-published `@hathora/cloud-sdk-typescript` 2.25.6 (npm, 2025-11-27) and the blog changelogs (Apr 2023 → Sep 2025).

| | |
|---|---|
| Pricing / licensing | Proprietary SaaS, usage-based: vCPU-seconds + egress bytes. Tiers (Nov 2024→): **Explore** free (100 vCPU-h/month, 32 concurrent vCPU, shared hardware, HTTP 402 past the cap), **Pro** (unlimited, single-tenant cloud, Fleet Management, business-hours support), **Enterprise** (bare metal + cloud burst, custom hardware, 24/7 paging support, advanced DDoS, Prometheus export, extended retention). Published rates: 2024 $0.08/vCPU-h + $0.12/GB cloud egress ($0.01/GB metal); 2025 CPU $0.07/vCPU-h on-demand ($0.02 reserved), GPUs $0.35–$5/GPU-h, bandwidth $0.09/GB on-demand / $0 reserved. SDKs MIT. |
| Hosting model | Fully managed, multi-tenant control plane; compute = Hathora-operated bare metal (i3D, Servers.com) + cloud burst (AWS/GCP/Azure) in 14 regions; BYOC/on-prem node enrolment announced 2025. No self-hosting of the platform. |
| SDKs / platforms | REST (OpenAPI 3, Redoc), TypeScript SDK (npm), Go SDK (Mar 2025), Java SDK (Oct 2024), Unity plugin + C# SDK (FishNet/Mirror/Photon Fusion/NGO demos, WebGL via WSS), Godot 4.3+ plugin, Unreal via Dockerfile guide only, Node/JS guide; Go CLI (`hathora`) for CI/CD; Console web UI. |
| Release cadence | Monthly changelog posts (Apr 2023 → Sep 2025, ~30 posts), continuous SaaS deploys; API versions V1→V3 kept side by side. |
| Last release | Changelog **September 2025** (published 2025-10-06: multi-fleet, console build metadata, SOC 2 observation period). Last SDK publish 2025-11-27 (TS 2.25.6). After that: Fireworks AI acquisition and shutdown notice. |

## Top gaps for musubi

Ranked by how much a studio choosing between "Hathora-style managed fleets" and musubi would care. All items are `missing`/`partial` above.

1. **Game-server stdout/stderr capture, live tail, download, retention** (Hathora: `GetLogsForProcess follow/tailLines≤5000`, 72 h). Sketch: fleet providers pipe child stdout to a ring buffer + object/Postgres `server_logs` chunks; `GET /v1/server/gameservers/{id}/logs?follow&tail`, retention via the existing `[retention]` lease.
2. **Per-server resource metrics (CPU, memory, egress, connections) as time series**. Sketch: provider-side sampler (cgroup/`/proc`, docker stats, k8s metrics) → `server_metrics` table + Prometheus labels `fleet,server,build`; `GET …/gameservers/{id}/metrics?start&end&step`.
3. **Client SDKs (TypeScript, C#/Unity, Go, Java, Godot, Unreal plugin)**. Sketch: generate from `GET /openapi.json` (Speakeasy/openapi-generator) + hand-written realtime layer per language from `realtime.rs`.
4. **Admin console** (apps/fleets/servers/rooms/logs/metrics/teams). Sketch: React SPA against `/v1/admin/*` + `/v1/server/*`, per-operator keys already give RBAC and audit.
5. **Node-level autoscaling / cloud burst** (provision hosts, not just servers; utilisation thresholds 40–100 %, scale-from-zero, bare-metal-first). Sketch: `fleet.provider = hetzner|ovh|aws` node pools driven by the reconciler; target-utilisation policy next to `buffer`/`forecast`.
6. **Managed image builds from a tarball/Dockerfile + registry** (`CreateBuild/RunBuild`, global builds, build logs). Sketch: optional `musubi build` using BuildKit/kaniko into the operator's registry; FleetBuild gets `image_digest`, `size`, `log_url`.
7. **Resource requests/limits per server (CPU, memory, GPU) enforced by the provider**. Sketch: `FleetSpec{cpu, memory_mb, gpu}` → docker `--cpus/--memory/--gpus`, k8s resources, firecracker vCPU/mem.
8. **Rooms-per-process packing for dedicated servers** (`roomsPerProcess`, allocate N matches onto one server). Sketch: `slots` on FleetSpec; allocator fills servers with free slots before cold-starting; `/v1/gameserver/allocate` becomes per-slot.
9. **Egress metering and chargeback** per server/fleet/region. Sketch: provider counters (docker `NetworkStats`, cgroup, k8s) folded into `fleets/{id}/usage`.
10. **DDoS posture: trusted-IP allow-list per allocation with throttle mode, reputation blocklists, flood filtering on the UDP edge**. Sketch: `allocate {client_ips[]}` → edge admits listed IPs at full rate, others rate-limited; optional blocklist feed.
11. **Fine-grained token scopes** (`<resource>:read` / `read-write`, immutable, ≤ issuer's rights). Sketch: `POST /v1/admin/keys {scopes[]}` evaluated per ROUTES entry tag, keep roles as presets.
12. **Teams/organisations with e-mail invites and roles** for the future console. Sketch: `operators`, `invites` tables; SSO already exists.
13. **Process/server search & inventory API** (filter region/status/created-before, counts, exit reason, hosting class). Sketch: `GET /v1/server/gameservers?fleet&region&state&before&limit` + `exit_reason` captured by providers.
14. **Static allocation with rolling-upgrade constraints** (Target/Min/Max per region). Sketch: add `min_ready_during_upgrade`/`max_total` to `ScalePolicy`, reconciler honours them when a build is promoted.
15. **Engine samples and integration guides** (Unity/Unreal/Godot Dockerfiles, Photon Fusion / FishNet / NGO demos, CI recipes for pushing game-server images and `musubi fleet push`). Sketch: `examples/` + docs pages.

Takeaway for musubi: the features Hathora kept investing in until the end were **fleet/node economics** (hybrid bare metal + cloud, node shapes, utilisation-driven autoscaling, static allocation), **observability** (process/node metrics, logs, Prometheus export) and **DX** (SDKs in 4 languages, CLI, console). Game-feature breadth was never on their roadmap.
