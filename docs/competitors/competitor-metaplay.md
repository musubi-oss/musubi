# Competitor scan: Metaplay vs musubi

| | |
|---|---|
| **Product** | Metaplay — C# game backend SDK (server + Unity SDK + LiveOps Dashboard) for mobile/F2P live-service games; source-available, "designed for games with deterministic shared client/server logic" |
| **Pricing / licensing** | Source-available SDK under Metaplay license (free local dev). Cloud plans: Starter €195/mo (≤5 DAU, 1 mini env), Pre-launch €995/mo (≤100 DAU, 2 small envs), Production €1,985/mo + €2.95 per 1,000 monthly DAU above 5,000 DAU/day (2 small + 1 staging + 1 scalable prod env), Private Cloud custom. Support: Community (Discord, free), Standard €1,500/mo (NBD), Dedicated €5,000/mo (same business day, 2 eng-days/mo, Slack), Tailored; Critical Incident Response add-on €5,000/mo (24/7, 1h SLA). Source: https://metaplay.io/pricing |
| **Hosting model** | Managed "Metaplay Cloud" on AWS (EKS + Aurora MySQL Serverless + S3/CloudFront, Grafana/Mimir/Loki per environment, observability retention 3h/7d/90d by env tier) operated via Developer Portal + `metaplay` CLI; Private Cloud = same Terraform/Helm stack in customer AWS account (self-hosting docs are a single page + Terraform modules). Local dev: `dotnet run` with SQLite, no Docker. |
| **SDKs / platforms** | Unity (iOS, Android, Windows, macOS, WebGL; Unity 2022 LTS–6.2), .NET 10 server (.NET 8/9 on older releases), Blazor WebAssembly browser clients (preview R38), BotClient (C# headless), LiveOps Dashboard (Vue 3 + TS), CLI (Go; macOS/Linux/Windows). No Unreal, Godot or native mobile SDKs. |
| **Release cadence** | Major releases ~quarterly (R31 2024-12-16, R32 2025-04-02, R33 2025-06-18, R34 2025-09-10, R35 2025-11-27, R36 2026-02-11, R37 2026-05-28, R38 2026-08-26) + hotfix patch releases in between; 38 majors since R1 (2020-03-06). |
| **Last release** | Release 38 — August 26, 2026 |
| **musubi baseline used** | musubi-oss/musubi `main` (README feature table, `docs/parity.md`, `openapi.rs` ROUTES ≈618 routes, `realtime.rs` messages, 20 crates, 122 migrations, `musubi-cli`, `deploy/helm` + `deploy/terraform/{musubi,musubi-hetzner,musubi-ovh}`, `sdk/unreal` v0 scaffold). README status: "client SDKs and the admin console are not written yet". |

## Top gaps for musubi

Ranked by how much a studio choosing between the two would care.

1. **No client SDKs (Unity first)** — Metaplay ships a complete Unity SDK (connection mgmt with ~40 error codes, resumable sessions, offline mode, IAP manager, social logins, localization, incident reports). Sketch: generate a C# client from `openapi.json` + `musubi-idl`, wrap in a `MusubiClient` MonoBehaviour with WS transport, auto-reconnect/resume, typed events for chat/party/match; ship as UPM package.
2. **No admin console / LiveOps dashboard** — every Metaplay operation (CS, LiveOps, config publish, audit) has a UI. Sketch: Vue/React SPA over existing `/v1/admin/*` routes, starting with player search → player page (bans, mail, rewards, export, audit) and content version publish/diff/rollback; schema-driven forms from OpenAPI.
3. **No LiveOps event system** — server-owned scheduled events with phases (preview/active/ending-soon/review), UTC vs player-local, templates, targeting, dashboard editing. Sketch: `live_events` table + `/v1/admin/events` CRUD, phase scheduler job, audience evaluation at login, `EventUpdate` realtime push, WASM hook `on_event_phase`.
4. **No A/B experiments with config variants** — rollout %, capacity, segments, testers, Testing→Active→Paused→Concluded, analytics tagging. Sketch: `experiments` + `experiment_members` tables, variant = JSON patch over a content version, assignment at session start (hash bucket + weights), expose `experiment_ids` on event bus envelope.
5. **Game config pipeline is JSON-only** — no spreadsheet/CSV ingestion, typed libraries, `#key` columns, references, variants, build history with author/status, side-by-side diff UI. Sketch: `musubi content build --from sheet://id|csv` producing a bundle, add `content_builds` table (author, status, errors), typed schema per table via `musubi-idl`.
6. **No deterministic shared-logic model** — client-first execution + server re-validation with checksums is the core Metaplay value for mobile F2P. Sketch: document the WASM-module-on-both-sides pattern (same `.wasm` executed client-side via wasmtime/wasm3 in Unity, server validates action log with `TickHash`), add `ActionLog` message type.
7. **No per-player event log** — Metaplay keeps a retained, filterable event history per player/guild for CS. Sketch: `account_events` table fed by the existing event bus with retention options, `GET /v1/admin/accounts/{id}/events?keyword=`.
8. **No analytics sinks (S3/BigQuery)** — only Zanshin/webhooks. Sketch: add `AnalyticsSink` trait with batching (100 events/30s) and JSONL-to-S3 and BigQuery streaming-insert implementations configured in TOML.
9. **No maintenance mode / developer players / time-skip** — standard release-day tooling. Sketch: `maintenance` config with window + message returned as 503 + WS close code, `accounts.is_developer` flag that bypasses it and gates dev-only RPCs, `/v1/admin/dev/time-offset` applied to the server clock abstraction in non-prod.
10. **No localization delivery** — translation sheets → per-language archives on CDN with OTA updates. Sketch: `localizations` content table keyed by language, `GET /v1/localization/{lang}?since=` with ETag, CSV import in CLI.
11. **No client incident reports** — crash/connection-failure reports uploaded with logs, deduped, browsable. Sketch: `POST /v1/incidents` (gzip log + fingerprint), `incidents` table with dedupe counter, admin list/filter route.
12. **No asynchronous (defender) matchmaker** — needed for raid/PvP-vs-offline games. Sketch: in-memory MMR bucket cache per node fed by DB scan + `matchmaker_update` messages, `POST /v1/matchmaker/async/find {mmr, exclude[]}` returning one candidate, eviction after match.
13. **Offer system lacks placements/groups/precursors/per-player force-enable** — Metaplay offers have 4 limit types, precursor chains, priority per placement, player-local schedules, seen/purchased stats. Sketch: extend `store` with `placement`, `priority`, `cooldown_secs`, `precursors[]`, per-account activation counters, `POST /v1/admin/store/{id}/force {account_id}`.
14. **Segments are flat filters** — Metaplay segments compose (`RequireAny/All`), support time-since-login, account age, hash-bucket subsets, country. Sketch: audience DSL with `any_of`/`all_of` referencing other audiences, built-in properties (`account_age`, `last_login_age`, `bucket(N)`, `country` via GeoIP).
15. **Observability packaging** — no shipped Grafana dashboards/alert rules, no business metrics, no GeoIP. Sketch: add `deploy/grafana/*.json` + `PrometheusRule` in the Helm chart, a daily KPI aggregator (DAU/revenue/retention) exposed at `/v1/admin/metrics/business`, optional MaxMind GeoLite2 lookup at login.
