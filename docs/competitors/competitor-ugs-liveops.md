# Competitor teardown: Unity Gaming Services — backend / LiveOps (vs musubi)

| | |
|---|---|
| **Product** | Unity Gaming Services (UGS) LiveOps & backend: Authentication, Cloud Code, Cloud Save, Economy, Leaderboards, Remote Config, Friends, Analytics, Push Notifications, Game Overrides, Access Control, Triggers, Scheduler (+ adjacent: Player Management, Secret Manager, Observability, Moderation, Webshop, Live Content/Live Releases, Targeting Rules) |
| **Pricing / licensing** | Proprietary SaaS, pay-as-you-go with a free tier per service (`services/pricing-and-billing`). Analytics (and Push, Game Overrides/Experimentation, which are bundled into Analytics) are MAU-metered: 0–50,000 MAU free, >5,000,001 MAU "contact sales"; Leaderboards also MAU-priced and archived versions count toward it. Fair-usage caps once past free tier: 500 custom events per MAU, 0.05 s of SQL Data Explorer time per MAU. Cloud Code billed per invocation + GB-s with a 25,000 scheduler invocations/month allowance included. Budget alerts and a Cost & Usage dashboard (≈12 h delay). Exact $/unit tables live on unity.com (not in docs). Terms: Unity is GDPR Processor, developer is Controller; COPPA designation is chosen at project creation. |
| **Hosting model** | Fully managed multi-tenant SaaS (Unity-operated; Analytics data lives in GCP EU-WEST4 / US-CENTRAL1). No self-hosting of the LiveOps services — the "Self-Hosted Deployment" docs set (115 pages) covers Unity Cloud *Create* services (asset manager, Keycloak identity, ArgoCD on your Kubernetes), not Authentication/Cloud Code/Economy etc. No published SLA/uptime numbers in the docs. |
| **SDKs / platforms** | Unity C# packages: `com.unity.services.core` 1.17, `authentication` 3.7, `cloudcode` 2.10 / 3.0.0-exp, `cloudsave` 3.4, `economy` 3.5, `leaderboards` 2.3, `remote-config` 4.2, `friends` 1.2, `analytics` 6.3, `push-notifications` 3.0, `deployment` 1.7, `wire` 1.4 (WebSocket push), `apis` 1.1 (generated service clients), plus Unity IAP 5.4. Minimum Editor 2021.3 → 2022.3 (2026). Authentication also has an Unreal Engine SDK and a C/C++ "Native SDK"; every service has REST APIs + OpenAPI specs; server-side logic in JavaScript (Node) scripts or C# (.NET 7/8/9) modules; Cloud Code JS SDKs wrap the services. UGS CLI (`ugs`) 2.0 for config-as-code and CI. |
| **Release cadence** | Monthly release-notes roll-up (`services/release-notes`), every month from July 2022 to July 2026 (46 monthly sections); individual SDK packages ship patch releases every 1–3 months, minors ~2–4×/year. |
| **Last release** | July 2026 section: In-App Purchasing SDK 5.4.2 / 5.4.1, Cloud Code SDK 2.10.4 (last docs-dated release-notes entry as of this scan, 2026-10-18). |

Legend for `musubi_status`: **have** = present (evidence cites README row / route / crate), **partial** = present but weaker (says what), **missing** = nothing comparable after `rg` in the repo, **n/a** = not meaningful for a self-hosted OSS backend. Musubi evidence refers to `README.md`, `docs/parity.md`, `crates/musubi-server/src/openapi.rs` (`ROUTES`), `crates/musubi-proto/src/realtime.rs`, migrations under `crates/musubi-server/migrations/`, and the `musubi-*` crates.

## Top gaps for musubi

Ranked by how much a studio choosing between UGS and musubi would care.

1. **Client SDKs and engine tooling (Unity C#, Unreal, native)** — UGS ships a package per service plus Editor deployment window and auto-generated module bindings; musubi has only an Unreal scaffold. Sketch: generate C#/C++ clients from `GET /openapi.json` + IDL bindings (`openapi-generator` templates in `sdk/`), add a thin WS/QUIC client, publish as UPM package and Unreal plugin.
2. **Admin console / Player Management UI** — UGS dashboard covers player lookup by external id, identities, Cloud Save edit, economy grants, moderation history, disable/delete, logs; musubi exposes all of it via `/v1/admin/*` only. Sketch: a static SPA served by the binary under `/admin`, backed by existing admin routes + operator SSO.
3. **Mainstream server-logic languages (JavaScript / C#)** — Cloud Code accepts JS scripts and .NET modules with templates, unit-test scaffolds, local debugger; musubi requires compiling to WASM. Sketch: bundle a JS→WASM path (Javy/QuickJS component) behind `musubi module publish script.js`, and document NativeAOT-LLVM for C#.
4. **Remote Config targeting layer (overrides, rollout %, priority, schedule, `configAssignmentHash`) and A/B experiments in core** — today variants require Zanshin. Sketch: `configs.<name>.overrides[]` {audience | expression, percent, priority, start/end} resolved in `GET /v1/configs`, sticky hash of assignments returned to clients and accepted by store/RPC; exposure events for experiments.
5. **Product analytics (Event Manager, dashboards, Data Explorer, funnels, SQL explorer, audiences from behaviour)** — musubi only emits events. Sketch: keep Zanshin as the analytics plane but add a client-auth `POST /v1/events` collector with schema registry and retention, plus a ClickHouse sink option.
6. **Declarative Triggers + runtime Scheduler API** — UGS lets ops wire `event → script/webhook` with CEL filters and create cron/interval schedules via API/dashboard with DLQ replay-all; musubi needs module redeploys for hooks and cron. Sketch: `/v1/admin/triggers` (event type, CEL filter, target RPC/webhook) and `/v1/admin/schedules` (cron/interval/window → RPC) persisted in Postgres, executed by the existing timer sweeper.
7. **Cloud Save Files (large per-player save blobs)** — 1 GiB files, 200 per player, presigned upload/download, metadata, write locks. Sketch: `POST/GET/DELETE /v1/storage/files/{key}` issuing presigned S3 URLs via the existing `[ugc.s3]` backend with per-player quotas.
8. **Resource-policy Access Control** — project and per-player Allow/Deny statements over service URNs let studios close client write paths (e.g. forbid client score submission) without code. Sketch: `[access]` policy table + `/v1/admin/access/policies[/{account_id}]` evaluated in the auth middleware with route patterns and `Read|Write` verbs.
9. **Webshop / direct-to-consumer payments** — UGS now offers a hosted branded storefront, payment providers, remote catalog and Apple/Google external-purchase compliance. Sketch: payment-provider trait in `musubi-economy` (Stripe/Xsolla/PayPal webhooks) + a hostable storefront template reading `/v1/store`.
10. **Authentication coverage gaps: Code-Link device-code flow, Oculus/Meta provider, Google Play Games server-auth-code flow, native C/C++ client, restricted/down-scoped tokens** — Sketch: `/v1/auth/code/*` device flow table with TTL; Meta user-proof and Play Games token exchange providers; `POST /v1/auth/restrict` to mint a session with a subset of claims/limits.
11. **Push reporting and recurring campaigns** — opens/purchases attribution 24 h–30 d, recurring sends, audience campaigns. Sketch: `POST /v1/push/opened` ack endpoint, `push_opens` table joined to purchases, `cron` field on `/v1/server/push/schedule`.
12. **Standard API ergonomics: `RateLimit`/`Retry-After` headers, API lifecycle/deprecation policy, per-endpoint published quotas** — Sketch: emit headers from the token-bucket middleware and document limits per route in `openapi.rs` metadata.
13. **Hosted log query (Observability API with OTel filter language) and per-trigger/per-module log views** — Sketch: optional Loki/ClickHouse sink + `GET /v1/admin/logs?from=now-3h&filter=` proxy.
14. **Secret Manager hierarchy & RBAC/SCIM** — org/project/env inheritance, roles per service, SCIM provisioning. Sketch: `secrets` table with scope precedence and `secret.get` host op; map SSO groups → fine-grained roles; optional SCIM 2.0 endpoints.
15. **Small leaderboard/storage parity items** — `versionId` guard on score submission, random `sampleSize` queries, 6M-leaderboard scale statement. Sketch: `window_id` on record submit (409 when stale), `?sample=N` on list, publish a scale benchmark via `musubi bench`.
