# Competitor teardown: Beamable vs musubi

| | |
|---|---|
| **Product** | Beamable — "Live Game Platform": managed game backend (accounts, content, inventory/commerce, stats, leaderboards, tournaments, events, groups, mail/notifications, cloud save, C# microservices + MongoDB microstorage, matchmaking/lobbies/relay, A/B testing, analytics, LiveOps Portal/Console) for Unity, Unreal and web. Docs: https://docs.beamable.com/ (now https://help.beamable.com/, built from https://github.com/beamable/docs). |
| **Pricing / licensing** | Proprietary SaaS. Free tier (limited monthly API calls, developer seats, 1 microservice × 3 realms); paid subscription tiers scale with developer count; usage billing on API calls, seats and microservice instances (each service × realm = 1 instance), invoiced monthly; Enterprise "service plans" with dedicated infrastructure; license at beamable.com/license (source: docs/best-practices, performance-scalability-overview). SDKs are source-available on GitHub (BeamableProduct, UnrealSDK, beamable-sdk-js is MIT). |
| **Hosting model** | Multi-tenant SaaS on AWS us-west-2 (3 AZs, ECS autoscaling, MongoDB Atlas sharded); "Beamable Private Cloud" installed by Beamable into the customer's AWS account in any region; no self-hosting. Game servers are not hosted — `IFederatedGameServer` hands off to Edgegap/Hathora/Agones/custom. |
| **SDKs / platforms** | Unity SDK `com.beamable` 6.2.0 (Unity 2021.3 → 6.3; iOS/Android/Steam/WebGL), Unreal SDK 2.3.0 (UE 5.4–5.6, Windows/Linux/Android/iOS, C++ + Blueprints), Web SDK `@beamable/sdk` 1.2.1 (TypeScript, Node + browser), Beam CLI `Beamable.Tools` 7.3.0 (.NET 8/10 tool), C# microservice runtime `Beamable.Microservice.Runtime` 7.3.0 (Docker x64), Portal toolkit `@beamable/portal-toolkit` 0.4 (unreleased), REST API (~350 documented endpoints) + autogenerated OpenAPI clients. |
| **Release cadence** | Unity SDK minor every ~2 months + patches (2025: 2.1→4.0; 2026: 5.0 Feb, 5.1 Jun, 6.0 Jul, 6.1 Aug, 6.2 Oct); CLI in lock-step (4.1 Feb-2025 → 7.3 Oct-2026, 40+ releases) with LTS back-ports (4.3.x); Unreal 2.0 → 2.3 (4 minors in ~18 months); Web SDK ~monthly 2025, quarterly 2026; Portal 2–3×/year; backend changelog published once (Nov-2025). |
| **Last release** | 2026-10-08 (Unity SDK 6.2.0, Beam CLI 7.3.0, Microservice runtime 7.3.0). Web SDK 1.2.1 on 2026-06-03; Portal 1.7.0 on 2026-06-04; Unreal 2.3.0 (2026). |
| **musubi baseline** | https://github.com/musubi-oss/musubi — Apache-2.0 Rust backend, alpha; single clustered binary over Postgres; ~476 HTTP routes (`crates/musubi-server/src/openapi.rs`), 33 realtime message types (`crates/musubi-proto/src/realtime.rs`), 122 migrations, 15 CLI command groups, Helm + Terraform. README states client SDKs and the admin console are not yet written. |

Status legend: `have` = clearly present in musubi (evidence cited), `partial` = exists but weaker (what is weaker stated), `missing` = nothing comparable (grepped), `n/a` = not meaningful for a self-hosted OSS backend.

## Top gaps for musubi

Ranked by how much a studio choosing between Beamable and musubi would care (status in parentheses).

1. **Engine SDKs — Unity, Unreal, Web/TypeScript (missing).** Beamable's whole value is `BeamContext`/`UBeamRuntime` + generated clients + editor windows; musubi has only HTTP/WS/QUIC. Sketch: generate typed C#/TS/C++ clients from `openapi.rs` + `realtime.rs` (one codegen crate, three templates), ship a Unity UPM package and an Unreal plugin that wrap auth/token refresh/WS reconnect/storage cache, and keep them in CI against the server.
2. **Admin console / Portal (missing).** Player lookup, inventory/currency/stats edits, leaderboards, mail/campaigns, realm config, microservice logs, deployments. Sketch: a React (or HTMX) console served by `musubi-server` under `/console`, built only on the existing `/v1/admin/*` routes, with pluggable "views" so studios can add pages (parity with MicroViews later).
3. **Built-in analytics / BI (partial).** Beamable gives Athena SQL access, platform KPI events (sessions, spend windows, retention), per-player event views and Amplitude/Mixpanel/S3 forwarding. musubi only emits to a bus/Zanshin. Sketch: ClickHouse (or DuckDB-over-Parquet) sink + `/v1/analytics/query`, auto-derived session/spend/retention stats per account, and a KPI page in the console.
4. **A/B testing & cohort data overrides (missing).** Trials with allocation %, custom stat criteria, lifecycle, per-cohort content/cloud-data overrides. Sketch: `experiments` table (allocation, criteria over player stats/audiences, sticky assignment), `/v1/experiments/assign`, and overlay of cohort overrides onto `/v1/configs` + content bundle resolution.
5. **C# (.NET) cloud code path (partial).** Many Unity studios will not write WASM/Rust. Sketch: a `musubi-host` gRPC/HTTP contract for out-of-process services (any language), a .NET template that implements `[ClientCallable]`-style attributes against it, plus container deploy via the existing fleet providers; keep WASM for low-latency hooks.
6. **Content authoring workflow in-engine (partial).** Typed ContentObject classes, local-vs-realm status, auto-sync, conflict resolution, snapshots, tags, publish history diff, promotion dev→staging→prod. Sketch: extend `musubi-idl` to emit C#/C++ content types, add `musubi content status/diff/publish/promote/snapshot/tag` CLI backed by content bundle versions, and expose promotion between environments as one API call.
7. **Inventory / identity federation hooks (missing/partial).** `IFederatedInventory` (external or NFT-backed items with proxy state + async reload), `IFederatedPlayerInit`, challenge/solution wallet auth. Sketch: add `hook_inventory_external` + `hook_account_init` to the module ABI, plus `/v1/server/inventory/proxy/{reload,state}` to replace cached external state.
8. **Campaigns & mass communication wizard (partial).** Mail/email/push/announcement campaigns targeted by stats and activity dates (install, last session, last purchase). Sketch: `campaigns` entity (type, content, audience, schedule, date-point rule) executed by the workflow engine; auto-maintain `last_session_at`, `last_purchase_at`, purchase/spend/session rolling-window stats per account.
9. **Microservice-grade observability UX (partial).** Log explorer with searchable attributes, per-request dynamic log levels (by player/path), CPU/mem per service, deployment history. Sketch: structured module logs → ClickHouse/Loki with `account_id`/`path` attributes, `/v1/admin/modules/{m}/log-rules`, Grafana dashboards shipped in `deploy/helm`.
10. **Scheduled-job management API (partial).** Named/unique jobs, search by name/source, upcoming executions (first 1000 for cron), execution state history (ENQUEUED→DONE/ERROR), modify/cancel, suspended jobs. Sketch: expose the existing schedule/timer tables via `/v1/server/jobs*` with execution log + preview of next N fire times.
11. **Cloud Save file-sync semantics (partial).** Manifest with MD5-keyed objects, local cache, conflict callbacks, force upload/download, 5 MB files, portal download/upload per player. Sketch: `/v1/storage/files` manifest + presigned blob URLs on top of existing blob store; SDK-side sync loop once SDKs exist.
12. **Moderation provider for all player text (partial).** OpenAI moderation (assert vs mask) applied to group names/tags, aliases, MOTD and chat with realm-level toggle. Sketch: central `moderation` service with provider trait (local list, OpenAI, webhook), invoked by chat, groups, display-name and UGC paths; mask vs reject per field.
13. **Pre-built platform telemetry & player enrichment stats (partial).** `SESSIONS_7D`, `SPEND_28D`, `DAYS_SINCE_INSTALL`, `PURCHASES_TOTAL`, `TRIALS` auto-populated per player and queryable for segmentation. Sketch: nightly + on-event rollups into `player_stats` with reserved keys, consumed by audiences.
14. **Realm hierarchy & scoped operator roles (partial).** Child realms inheriting roles, archive realm, promote content between realms, launch message, API usage page. Sketch: `environments` parent pointer + role inheritance in operator RBAC, `/v1/admin/environments/{id}/promote`, usage counters per key/environment.
15. **In-game admin console + offline cache + Stripe/web payments (missing).** Smaller items a studio notices: runtime debug console gated by scope, read-only offline cache, Stripe checkout for web games. Sketch: console comes with the SDK work; Stripe provider in `musubi-economy` alongside the 9 store validators.

- **Platform reach.** Unreal 2.2 (UE 5.6), 2.3 (iOS), Unity 6.3 + .NET 10; samples now cover Steam tickets, EOS OIDC, Google, Game Center.
- **What is NOT moving:** no new core gameplay services in 18 months (no new matchmaking, no server hosting, no chat replacement); investment is in tooling, observability, console extensibility and web SDK. Backend changelog shows only "player scoped rate limiting" (Nov-2025).
