# Competitor teardown: Azure PlayFab vs musubi

| | |
|---|---|
| **Product** | Azure PlayFab — Microsoft's managed game backend (Core services: identity, player data, economy v1/v2, progression/leaderboards, segments, CloudScript/Azure Functions, PlayStream/Insights/analytics, Experiments, Multiplayer Servers (MPS), Lobby, Matchmaking, Party networking/chat, Real-Time Notifications) |
| **Pricing / licensing** | Proprietary SaaS. Plans: Free to Start (Development Mode only: 100k unique users/title, 10 dev titles/studio, capped meters), Pay-as-you-go, Standard, Premium, Enterprise. Launching a title to Live is permanent and needs a paid plan. Usage meters: profile reads/writes/storage, content & config, PlayStream events, telemetry events, entity statistics, entity leaderboards, CloudScript GB-s + executions, Insights credits/retention, MPS VM core-hours + egress, Party connectivity/voice/Cognitive Services, Economy v2 catalog request-size meters, Experiments, Churn Prediction. Gated features: support tickets (Standard+), 24/7 emergency escalation (Premium/Enterprise), MPS core quota increases (paid), Churn Prediction (paid opt-in), Party free only for Xbox Live users and dev-mode titles. Many newer features are private/public preview (Catalog Views, Event Partitioning, Advanced Segmentation custom properties, Sweepstakes, VmStartupScript, Apple/Google subscription redemption). |
| **Hosting model** | Fully managed multi-tenant SaaS on Azure; no self-hosting. Game servers run in Azure VMs (MPS) in ~17 Azure regions (Party: 16 regions in 3 egress zones). Data residency not selectable per title (Insights/ADX exports to West US 2 preferred). |
| **SDKs / platforms** | Generated SDKs (Apache-2.0, GitHub PlayFab/*): C#/.NET, Unity (+Editor Extensions), Unreal (Marketplace plugin), C++ (XplatCpp, legacy), Unified C/C++ SDK (Win32, GDK, Android, iOS, macOS, Linux), Java/Android, JavaScript, Node.js, Python, Lua (Corona/Defold), Cocos2d-x, PowerShell (MPS), Postman. Multiplayer (Lobby/Matchmaking) C++ SDK + Unity/Unreal; Party C/C++ SDK on Android, iOS, Linux, macOS, Windows, Switch, PS4, PS5, GDK + Unity/Unreal plugins (console builds via approval); GSDK for servers (C#, C++, Java, Unity, Unreal). REST for everything else. |
| **Release cadence** | Services SDK: bi-weekly dated releases 2015–2024 (22–32 entries/year; 24 in 2023, 13 in 2024), then a single 2025 entry (250117). Unified C SDK: quarterly-ish (2306, 2310, 2403, 2406, 2410, 2504). Platform: continuous, no versioned service changelog beyond SDK notes + "What's new" page. |
| **Last release (observed)** | Services SDK notes: 2025-01-17 (250117). PlayFab C/C++ SDK: 2504.0.0 (April 2025). GitHub releases API for the SDK repo queried returned latest `v2.10.0` 2023-08-29 (that repo is no longer the primary release channel — see Coverage). Docs repo last commit: 2026-01-13. |
| **musubi snapshot compared** | musubi-oss/musubi @ 552e2f1 (2026-10-18): 578 HTTP routes in `ROUTES`, 39 client / 37 server realtime messages, 122 migrations, 22 crates, CLI (`dev`, `module *`, `fleet *`, `schema`, `idl`, `deploy`, `migrate`, `migrate-nakama`, `migrate-playfab`, `export`, `import`, `doctor`, `config`, `bench`, `soak`), Helm/Terraform (k8s, Hetzner, OVH). |

Inventory totals: **270** features → have **123**, partial **64**, missing **57**, n/a **26**.

Reading the statuses: `n/a` is used only for things that make no sense for a self-hosted Apache-2.0 backend (billing UI, Azure VM SKUs, vendor SLA/support, managed-cloud quotas). Everything a studio could actually want from a backend — including a web console, analytics warehouse, client SDKs — is scored `missing`/`partial` even if musubi's README consciously defers it.

## Top gaps for musubi

Ranked by how much a studio choosing between the two would care. Status in brackets; one-line implementation sketch each.

1. **No admin console / Game Manager** [missing] — studios live in Game Manager (players page, economy editors, segments, automation, dashboards). Sketch: ship `musubi-console` (SPA served by the server at `/console`, operator OIDC login) over the existing `/v1/admin/*` routes; start with Players, Configs, Store/Items, Fleets, Audit.
2. **No official client SDKs or engine plugins** [missing] — PlayFab ships Unity/Unreal/C#/C++/JS/… SDKs plus Lobby/Party/GSDK libraries. Sketch: turn `musubi idl` output into maintained packages (UE plugin first per project rule, then Unity/C#, TS), with auth/session refresh, realtime transport, offline queue baked in.
3. **No event history / analytics warehouse / dashboards** [missing] — PlayStream monitor, Data Explorer (KQL), Trends, retention/revenue reports, daily email. Sketch: optional `musubi-analytics` sink (ClickHouse or Postgres partitions) fed by the event bus, with DAU/MAU/retention/ARPU materialised views and `/v1/admin/analytics/query`; keep Zanshin as the heavy path.
4. **No built-in A/B experiments** [missing] — Experiments: ≤9 variants, ≤10 variables, scorecards with p-values, exclusion groups. Sketch: `experiments` table + deterministic hash bucketing by account, variables exposed through typed configs overrides at login, scorecard job computing login/payer/retention deltas from the analytics sink.
5. **Segments with actions / rules engine (no-code LiveOps)** [partial] — PlayFab segments have enter/exit actions, scheduled bulk tasks, PlayStream rules with built-in actions. Sketch: materialise audience membership (`audience_members` with enter/exit events), add `rules` table (event → conditions → actions: grant, push, email, ban, tag, call module RPC) evaluated by the event bus.
6. **No client telemetry ingestion** [missing] — WriteEvents/WriteTelemetryEvents, Telemetry Keys (pre-login), SDK session/focus events, sampling. Sketch: `POST /v1/events` batch endpoint (≤10KB/event), `telemetry_keys` (≤5/project, write-only), per-event sampling ratio in config.
7. **No CDN/title content service** [missing] — presigned upload + CDN download URLs for arbitrary title files (50TB), file management UI, usage reports. Sketch: S3-compatible backend behind `/v1/content` with presigned PUT/GET, versioning, per-project quota; reuse UGC blob code.
8. **Entity files / per-player blob storage + Game Saves** [missing] — binary files per player/group/title (10 files/entity), cross-device Game Saves (256MB) with conflict callbacks. Sketch: `storage` collection kind `blob` with presigned upload, size quota per owner, version vector for conflict UI; expose over realtime for sync.
9. **Economy v2 catalog depth** [partial] — draft/publish workflow, localized titles/descriptions/keywords (40 locales), item images/files, OData search with fuzzy matching, catalog views to CDN, ratings/reviews with helpfulness and takedowns. Sketch: add `item_drafts`, `item_i18n`, `item_assets` tables, `tsvector` search over items, review table with votes.
10. **Party-style client networking + accessible voice** [partial] — managed relay mesh up to 128 devices, voice/text chat, STT/TTS, translation, moderation in-client. Sketch: keep Aurix for voice; add WebRTC SFU/relay mode to `musubi-transport` for P2P-less mesh and document a voice provider interface (Aurix/Vivox/own).
11. **Title News + localized templates + title default language** [missing/partial] — Sketch: `news` table with per-locale bodies and publish windows, `GET /v1/news?lang=`, extend push/email templates with `i18n` map and fallback chain.
12. **Scheduled segment tasks & per-task history** [partial] — Sketch: `tasks` table (cron, target audience, action list), worker fan-out through the job queue with per-run status/counters surfaced at `/v1/admin/tasks`.
13. **Character entity / per-character data, stats and inventory** [missing] — Sketch: generic `owner_kind=character` in storage/leaderboards/inventory with parent-account link; reuse owner-permission codes.
14. **Managed export connectors** [partial] — Azure Blob/ADX/Fabric sinks. Sketch: event-bus sinks for S3/GCS/Azure Blob (JSONL/Parquet batches) and Kafka/NATS in addition to HTTP webhooks.
15. **Rewarded ads, real-money payment providers, sweepstakes** [missing] — Sketch: `ad_placements` with daily caps + `RewardAdActivity`; checkout adapter interface (Stripe/Xsolla) producing wallet grants; raffle = reward table drawn over an audience.

## Coverage

**Method.** learn.microsoft.com was not crawled page-by-page; instead the public docs source repo `MicrosoftDocs/playfab-docs` (clone, `playfab-docs/` tree, 2,781 Markdown files, HEAD 2026-01-13) was walked exhaustively. Every file under the section roots below was extracted to text, run through a condensing filter (headings, tables, every sentence with a limit/quota/tier/preview/deprecation keyword) and read; key pages (pricing, limits, Economy v2 limits, leaderboards/statistics limits, matchmaking config, MPS lifecycle/billing, Party features, GDPR, tier limits, release notes 2023–2025, C SDK notes) were read in full. `pages_scanned` = 2,772 docs pages processed through this pipeline (+ GitHub: `PlayFab/API_Specs` Swagger set — 762 paths across Admin/Client/Server/Authentication/CloudScript/Data/Economy/Events/Experimentation/Groups/Insights/Localization/Multiplayer/Profiles/Progression/Leaderboards/State/Sweepstakes/Addon — and the GitHub releases API).

**Section roots read (files):** `api-references/` 1,437 (C API reference 1,186; PlayStream events + data types 251), `multiplayer/` 883 (lobby 384 incl. C++ reference, networking/Party 404 incl. Unity/C++ reference, servers 64, matchmaking 13, real-time-notifications 18), `sdks/` 87, `data-analytics/` 80, `live-service-management/` 71 (automation, config, add-ons, throttling), `economy-monetization/` 70, `player-progression/` 38, `community/` 36 (groups, friends, leaderboards, Party chat), `identity/` 30, `pricing/` 17, `release-notes/` 12 (2015–2025 + C SDK), `get-started/` 2, `miscellaneous/` 2 (tier limits, Xbox guidance), `demo-game/` 3, `resources/` 3, `whats-new/` 1. Of the 2,772, roughly 1,900 are generated API-reference pages (C/C++ functions, structs, enums, events) that were read at signature/heading level and summarised into the API-surface, events-catalog and SDK rows rather than one row each.

**musubi side:** full `README.md` (583 lines), `docs/parity.md`, `crates/musubi-server/src/openapi.rs` (578 routes), `crates/musubi-proto/src/realtime.rs` (39 client / 37 server messages), `crates/` (22), `crates/musubi-server/migrations/` (122 files), `crates/musubi-cli/src/*`, `deploy/`; `rg` run for every `missing` verdict (keyword list in the scan notes).

**Not accessed / caveats.** (1) Live learn.microsoft.com pages and `sitemap.xml` were not fetched; the docs repo is the canonical source of those pages, but any learn-only content (e.g. REST reference pages rendered from API_Specs, pricing calculator numbers) is covered via API_Specs and the repo's pricing pages only — exact per-meter $ rates are not in the docs repo and are not asserted here. (5) Unlisted PlayFab compliance certifications (SOC 2 etc.) are inherited from Azure and are not documented in the PlayFab docs; not asserted. (6) Row-level source URLs point at learn.microsoft.com paths derived from the repo file paths (`playfab-docs/<path>.md` → `learn.microsoft.com/gaming/playfab/<path>`), so a handful may have been renamed on the live site.
