## Top gaps for musubi

Ranked by how much a studio choosing between the stacks would weigh it; each with a one-line implementation sketch.

1. **Client SDKs + offline support (missing)** — Hiro ships Unity/Unreal/Godot/C++/TS/Dart/Python clients with typed models, deterministic startup and offline sync; musubi has only OpenAPI/IDL. *Sketch:* Generate SDKs from `GET /openapi.json` + IDL (OpenAPI Generator / `wit-bindgen`), start with Unity C# and Unreal C++; add a local-state cache + `POST /v1/sync` reconciliation endpoint for economy/achievements/energy.
2. **Native remote config with audience variants and A/B experiments (missing)** — Satori flags/variants/experiments and the Hiro Personalizer layer are the LiveOps core; musubi only proxies Zanshin flags. *Sketch:* Add `flags` + `variants` tables (schema-validated JSON, audience rule per variant, priority), evaluation at `GET /v1/configs` using the existing audience rules, and an `experiments` table with sticky hashed assignment + phases; expose `change_reason`.
3. **Player analytics pipeline (missing)** — Satori ingests client events, derives computed properties, retention/funnels/RoAS dashboards, data-lake export. *Sketch:* Add `POST /v1/events` (client, batched, taxonomy-validated), roll computed per-account aggregates (count/first/last/sum) into a properties table used by audiences, and a ClickHouse/Parquet sink; defer dashboards to Zanshin/Grafana.
4. **Cohort-based event leaderboards with tiers, score targets and re-rolls (partial)** — Hiro's flagship competitive loop (cohort_size ≤250, promotion/demotion %, idle demotion, score_target, max_rolls, tier_overrides). *Sketch:* Extend bucketed leaderboards: per-player tier, roll into open bucket at tier, `score_target`/`score_target_players` completion, `max_rolls` + cooldown, change-zone percentages and `tier_delta` computed at read time.
5. **Scheduled/recurring achievements with preconditions and sub-achievements (partial)** — Hiro achievements double as daily/weekly quests and battle-pass tracks via `reset_cronexpr`, `duration_sec`, `time_offset_sec`, `precondition_ids`, nested steps. *Sketch:* Add cron window + local offset + preconditions + parent/child to `achievements`; keep unclaimed rewards across phase boundaries; reuse quest period logic.
6. **Team-level meta systems: team achievements, gifts, store, mailbox, stats (missing/partial)** — Teams 2.0 mirrors every player system at group level with per-member contribution tracking. *Sketch:* Add `owner_kind = group` to achievements, mail and stats tables; store purchases payable from treasury; `group_gifts` with contribution window, tiers and contributor/non-contributor rewards.
7. **Player-created challenges from templates with invites (partial)** — Hiro Challenges: duo/group competitions, player-set duration/participants, invite/open search, rank rewards. *Sketch:* Add `challenge_templates` (server) + player `POST /v1/challenges` creating a private tournament instance with invites, `max_num_score`, reward tiers; reuse tournament scoring.
8. **Rewarded-video placements with ad-network S2S verification (missing)** — Mobile monetization staple; Hiro verifies ironSource / AppLovin MAX callbacks server-side with fallback. *Sketch:* Add `placements` definitions + `POST /v1/placements/{id}/start` and provider webhook endpoints verifying signatures, granting the reward table once per placement id.
9. **Incentives (referral codes) and donations (missing)** — Social acquisition/retention loops with dual rewards, caps, recipient account-age limits, per-user contribution limits. *Sketch:* Add `incentives` (code, sender/recipient reward tables, max_claims, max_recipient_age) and `donations` (request, contribute with cost, duration, max_count, dual rewards) on top of existing reward tables + mail.
10. **Reward depth: grantable reward/energy modifiers, item-set rolls, instance property rolls, mailbox routing per reward (partial)** — Hiro rewards are a composable DSL used by every system. *Sketch:* Extend reward entries with `kind = modifier|energy_modifier|item_set(tags, min, max, max_repeats)` and weighted `instance_props`; add `to_mailbox_ttl` on tables (deferred rewards already exist).
11. **Unlockables with slots/queues; energy overfill and reward-on-spend (partial)** — Chest-timer loops (slots, queue, skip cost per time unit, slot purchase) and energy as reward source. *Sketch:* Add `unlockable_slots` per account + queue ordering over existing timed graph nodes; add `max_overfill` and `spend_reward` to energy definitions.
12. **Operator messaging: templates with placeholders/translations, HTML email, cron schedules, OneSignal (partial)** — Satori inbox/push/email campaigns with property placeholders, per-language variants and live-event offsets. *Sketch:* Add `message_templates` (text/HTML/JSON, per-lang, `{{account.*}}` placeholders) rendered by the mail/push sender; add cron `message_schedules` with audience + offset-to-season/tournament.
13. **Per-player lifecycle journeys (partial)** — Satori Journeys orchestrate waits/branches/actions per player on their own clock. *Sketch:* Expose durable workflows as operator-authorable JSON (entry audience, wait/time-window, branch on account properties, actions: mail/push/flag-variant/webhook) with per-step counters.
14. **Cross-system progression preconditions, public/private stats, regional leaderboards (partial/missing)** — Hiro progression gates on achievements/stats/items/energy/currency thresholds; stats have public/private + whitelist; leaderboards fan out per region. *Sketch:* Add `requires` predicates over achievements/stats/inventory/wallet to graph nodes; add `visibility` + `client_writable` to stat defs; add `regions[]` on leaderboards with fan-out on write.
