# Competitor teardown: Rivet (rivet.dev / github.com/rivet-dev/rivet) vs musubi

| | |
|---|---|
| **Product** | Rivet — open-source "orchestrator for stateful workloads": Rivet Actors (durable, addressable processes with state, per-actor SQLite, queues, realtime connections, schedules), Rivet Workflows, agentOS (WASM micro-VMs), Dynamic Apps, Secure Exec, Sandbox Agent SDK, Rivet Cloud / Compute / BYOC. **Important:** Rivet pivoted away from being a game backend. The 2024 product (Dynamic Servers = autoscaling game lobbies, Game Guard DDoS/TLS, Matchmaker, Rivet Modules/OpenGB: identity, friends, lobbies, analytics, Godot/Unity/Unreal/HTML5 SDKs) was replaced by Rivet v2.0 (2025-09-04) and is no longer documented or supported. Current docs contain zero game-specific services (no matchmaker, leaderboards, accounts, chat, economy); a studio gets a generic actor runtime and builds those itself. |
| **Pricing / licensing** | Apache-2.0, self-hosting free with no usage limits. Rivet Cloud: Free $0 (100k Awake Actor Hours/mo, $5 compute cap, 1 vCPU max, 5 GB storage, 200M reads, 5M writes, 100 GB egress, community support), Hobby from $20/mo+usage (400k AAH, 8 vCPU max, 5 GB, 25B reads, 50M writes, 1 TB egress, email support), Team from $200/mo+usage (same limits, Slack+email support), Enterprise/BYOC custom. Usage: $0.05 per 1k Awake Actor Hours, $0.40/GB-month state, $0.20/M reads, $1/M writes, $0.15/GB egress; Rivet Compute $0.0000330/vCPU-s + $0.0000029/GiB-s billed per second (0.08–1 vCPU or 2/4/8; 128 MiB–4 GiB). Sleeping actors cost nothing. Startup program 50% off 12 months (YC / a16z Speedrun). Enterprise-only (paid): FoundationDB storage, multi-tenant cloud layer, SQLite backup + PITR, actor forking, ACL/RBAC, advanced ClickHouse analytics, OTel integration, Alertmanager/Prometheus/Grafana configs, Kubernetes manifests/Helm, air-gapped/sovereign deployment, priority support/SLA, FedRAMP/HIPAA hardening guidance. |
| **Hosting model** | (1) Rivet Cloud (managed control plane + storage) with Rivet Compute (managed Docker-based pools) or BYO workers on Vercel/Cloudflare/Railway/AWS/Kubernetes; (2) BYOC: Enterprise control plane + FoundationDB inside the customer's AWS/GCP VPC, managed via outbound operator; (3) fully self-hosted single Rust binary (`rivetdev/engine`) on Docker Compose, Kubernetes, Railway, Render, AWS ECS, Coolify, VM/systemd; storage filesystem/RocksDB (single node), PostgreSQL (multi-node, ~1,000 concurrent actors), FoundationDB (Enterprise). Workers connect outbound; serverless workers are invoked over HTTP. |
| **SDKs / platforms** | RivetKit TypeScript (Node 22+, Bun, Deno; Hono/Express/Elysia; Next.js; Cloudflare Workers, Supabase Edge, Vercel Functions, AWS Lambda, Cloud Run, Freestyle via WASM runtime), React (`@rivetkit/react`), Rust SDK + client (beta), Swift/SwiftUI client (iOS/macOS/tvOS/watchOS), Effect.ts SDK (beta), generated Go/Rust/TypeScript engine API SDKs, OpenAPI 2.2.0 + AsyncAPI 2.4.0 specs, CLI `@rivetkit/cli`, MCP server, AI "skills" package. No game-engine SDKs (Unity/Unreal/Godot were dropped with v1). |
| **Release cadence** | 116 GitHub releases; v2.0.21 (2025-10-26) → v2.3.27 (2026-10-12): roughly weekly patch releases (every release is cut as a patch by policy), plus ~weekly changelog posts in late 2025 and 1–3 launch posts per month in 2026. |
| **Last release** | v2.3.27, 2026-10-12 (last commit scanned 2026-10-13). |

Status legend: `have` = musubi has it (evidence cited: README row / route / crate / file), `partial` = exists but weaker (weakness stated), `missing` = nothing comparable (verified with `rg -i`), `n/a` = not meaningful for a self-hosted OSS backend.

## Top gaps for musubi

Ranked by how much a studio choosing between the two would care.

1. **Client SDKs (TS/JS, React, Swift, Rust, Unity/Godot, finished Unreal)** — Rivet has typed clients for every web/mobile runtime; musubi has none shipped. Sketch: generate clients from `GET /openapi.json` + `musubi idl` (TS first), publish `@musubi/client` with reconnect/resubscribe and postcard/JSON encodings; finish `sdk/unreal` (binary framing, QUIC, reconnect) and compile it in CI.
2. **Admin console / dashboard with live inspector** — Rivet: actor list/search, state editor, connections, logs, SQLite browser, workflow history/replay, pool errors. Sketch: ship a static SPA served at `/ui` over the existing `/v1/admin/*` routes; first tabs = matches/worlds (state snapshot + presences), accounts, flags, fleets, audit.
3. **Generic durable actor primitive with per-actor storage (SQLite-class) and sleep/wake** — Rivet actors persist state, sleep for free and wake on request; musubi only has match/world actors. Sketch: add `entity` module kind keyed by user-defined compound key, state snapshot in Postgres JSONB + journal, idle→unload→reload on `rpc`, `get_or_create` route.
4. **Per-actor durable queues/mailbox and alarms (`schedule.after/at`, programmable cron with history)** — Sketch: `musubi.schedule {at|after, export, args}` host op backed by `schedules.rs`, plus `queue` table with `skip locked` consumer in the match tick; expose `/v1/server/matches/{id}/queue`.
5. **Log tail / debugging CLI and troubleshooting docs** — Sketch: `musubi logs --follow --match <id> --json` over a `/v1/admin/logs` SSE route fed by the tracing subscriber ring buffer; write runbooks for "no fleet capacity", "node lost", "WS drops".
6. **Docs site + AI skill/MCP surface** — Rivet pages have Copy-Markdown, skills package, MCP server. Sketch: split README into mdBook under `docs/`, publish `/llms.txt`, add a small MCP server wrapping admin routes (list matches, call rpc).
7. **Namespaces / multi-environment isolation in one control plane (incl. per-PR preview namespaces)** — Sketch: add `namespace_id` to keys, matches, storage collections; `musubi deploy --namespace pr-123 --create`; GitHub Action that destroys it on PR close.
8. **Live WebSocket migration & WS hibernation across node failover/upgrade** — Sketch: edge holds the client socket; on match re-host the edge replays `match_join` and resumes from the last acked sequence (`session_resume` already exists). Hibernation: keep the edge socket while the cell is unloaded, wake on first input.
9. **Fine-grained scoped JWT grants for third parties / browsers (publishable-key tier)** — Sketch: `POST /v1/admin/tokens {grants:[{resource, ids, ops}], ttl≤24h}` verified at the edge; a `pk_`-style key limited to `match_join`/`rpc` for web builds.
10. **Backup / PITR / upgrade runbook** — Sketch: document `pg_dump` + journal replay; add `musubi backup` wrapping export with point-in-time via match journals; write upgrade order + compat policy in `docs/`.
11. **Serverless/edge worker mode for game logic** — Rivet runs actors on Vercel/Cloudflare/Lambda. Sketch: optional `musubi-runtime` remote executor invoked over HTTP with start payload (snapshot) for low-traffic modules; lower priority for authoritative tick loops.
12. **Shipped Grafana dashboards + alert rules + ClickHouse analytics sink** — Sketch: `deploy/grafana/*.json`, Prometheus rules in Helm, `analytics_sink = clickhouse` writer for the event bus.
13. **Per-query profiling and trace propagation into module calls** — Sketch: fingerprint sqlx queries, histogram per route; propagate `traceparent` through `rpc`/`match_input` into guest `CallContext`.
14. **PaaS one-click deploys (Railway/Render/Coolify) and published multi-arch images** — Sketch: push `ghcr.io/musubi-oss/musubi` (amd64+arm64) from CI, add `docker-compose.yml` and a Railway template.
15. **Starter templates & guides** — Sketch: `templates/` with Unreal + TS web examples wired to `musubi dev`, plus 6–8 guides (chat, leaderboard, matchmaking, authoritative match, meshing, LiveOps).
