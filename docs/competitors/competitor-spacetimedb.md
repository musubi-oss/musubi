# Competitor scan: SpacetimeDB (Clockwork Labs) vs musubi

| | |
|---|---|
| **Product** | SpacetimeDB — "a database that is also a server": in-memory relational DB + WASM/V8 module runtime; game/app logic runs as *reducers/procedures/views* inside the database, clients subscribe to tables over WebSocket and keep a local cache. Flagship customer: BitCraft (Clockwork Labs' own MMO). |
| **Pricing / licensing** | Source available under **Business Source License (BSL 1.1)** (`LICENSE.txt`, "SpacetimeDB Business Source License Agreement", Licensed Work 2.13.0). Additional Use Grant: **max 1 production instance**, no offering it as a database service. Change Date **2031-10-14** → AGPLv3 (with linking exception). GitHub API reports `NOASSERTION`. Managed **Maincloud** tiers: Free $0 (2,500 TeV/mo ≈ 3M calls, ≈12.5 GB egress, ≈1 GB storage, 20 projects × 5 DBs, 5 collaborators/DB, 1 h metrics, auto-pause after 1 week idle); Pro $25/mo (100k TeV ≈ 120M calls, ≈500 GB egress, ≈40 GB storage, +2,592 TeV per $1, replication + 7-day PITR backups, 1-month metrics, 10 collaborators, email support, SLA, DDoS); Team $250/mo (250k TeV, ≈1.25 TB egress, ≈100 GB storage, org permissions, read-only dashboards, dedicated node reservation, 30-day PITR, 10 org users then $25/user, priority support); Enterprise (custom: on-prem/BYO cloud, custom replication, custom license, 24/7 support, onboarding engineer). Energy (TeV) metered on bytes scanned/written, index seeks, CPU instructions, egress, storage. |
| **Hosting model** | (a) Maincloud serverless (scale-to-zero, dynamic scaling, machines up to ~80 cores/256 GB, replication only on Pro+); (b) self-hosted `spacetimedb-standalone` single node (systemd/Nginx guide, Docker image `clockworklabs/spacetime`, Railway template); (c) Enterprise on-prem with replication. | **SDKs / platforms** | Server modules: Rust, C#, TypeScript (V8), C++. ## Top gaps for musubi

Ranked by how much a studio choosing between the two would care (most SpacetimeDB adopters come for "no server code to host + typed live state in the client").

1. **Client SDKs (C#/Unity, TypeScript, Rust, Unreal, Godot) with local state cache and reconnect** — `missing`. Sketch: generate typed clients from `openapi.json` + IDL (openapi-generator for REST; hand-written WS core per language with auto-reconnect/resume using `0040 resumable sessions`), ship Unity UPM + npm packages first.
2. **Filtered live query subscriptions (subscribe to "rows where …" and receive deltas)** — `partial`. Sketch: add `QuerySubscribe {collection, filter-expr}` to realtime.rs, evaluate filters in `musubi-storage` on write using Postgres LISTEN/NOTIFY or the existing storage-update bus, dedupe identical queries per node.
3. **Server-defined views / derived read models** — `missing`. Sketch: module-declared `view(name, fn)` in `musubi-runtime` recomputed on the touched collections' writes, exposed as subscribable collections.
4. **Admin web console (DB/table browser, SQL console, logs, metrics, users)** — `missing`. Sketch: SPA over existing `/v1/admin/*` + `/metrics` + a new `/v1/admin/sql` (read-only, role-gated) and `/v1/admin/logs` tail endpoint.
5. **Developer-defined typed tables/schema-as-code with automatic compatible migrations** — `partial`. Sketch: extend IDL to declare persistent collections with typed columns + indexes; `musubi schema diff/apply` generates additive Postgres DDL (add table/column-with-default/index) and rejects destructive changes unless `--break-clients`.
6. **Multi-language server modules (C#, TypeScript, C++) with typed data access** — `missing`. Sketch: publish `musubi-module-abi` as a stable wit/WIT world; ship C# (NativeAOT-LLVM→wasm) and AssemblyScript/TS (via Javy/QuickJS) bindings that wrap the existing host-call JSON ops.
7. **Module HTTP handlers (custom routes served by module code)** — `missing`. Sketch: `ANY /v1/modules/{name}/route/*` dispatching to a module export `http(req) -> resp` under fuel cap, with bearer validation done by the host.
8. **Typed codegen from schema (`spacetime generate` equivalent)** — `partial`. Sketch: `musubi idl generate --lang ts|csharp|rust|cpp` emitting typed realtime message + storage models; reuse `musubi-idl` AST.
9. **Module lifecycle hooks `client_connected/disconnected` and per-module log streams** — `partial`. Sketch: fire host events on `Session` open/close into subscribed modules; persist module `log` host-op output to a ring buffer per module exposed at `/v1/admin/runtime/modules/{name}/logs?follow`.
10. **Procedures with outbound HTTP from module code** — `partial`. Sketch: `http.fetch` host op (allowlist, timeout, body cap, kill-switch config) executed outside any DB transaction, mirroring SpacetimeDB's `module-http.enabled`.
11. **Built-in backups / PITR story for self-hosters** — `partial`. Sketch: document + script `pg_basebackup`/WAL-G in Helm/Terraform, plus `musubi export --snapshot` including world/match journals; add `musubi restore`.
12. **Per-database/module environment variables with typed declarations and versioned updates** — `partial`. Sketch: module manifest `env { KEY: type, required }`, stored encrypted in `0085 content envs`, validated on module push, `PATCH /v1/admin/runtime/modules/{name}/env`.
13. **MCP server / AI-agent tooling** — `missing`. Sketch: `musubi mcp` exposing describe (openapi/idl), fixtures, read-only SQL, logs, and module push as MCP tools over stdio.
14. **Framework integrations for web clients (React/Vue/Svelte hooks)** — `missing`. Sketch: after TS SDK, publish `@musubi/react` with `useMusubi`, `useStorage(collection)`, `useChannel`, `useLeaderboard` hooks.
15. **Project templates / `musubi init`** — `partial`. Sketch: `musubi init --template unity|unreal|web` creating config, module skeleton, Docker compose with Postgres, and a sample client.
